# DOMAIN.md — 도메인 로직 설명

## Room JSON 스키마

`packages/domain/src/index.ts`에 정의된 공통 타입입니다.
iOS(RoomPlan) / Android(ARCore) 스캔 결과를 모두 이 형식으로 변환합니다.

### 좌표계
- 단위: cm
- 원점(0,0): 방의 좌상단
- x축: 오른쪽, y축: 아래쪽

### 가구 회전
- `rotation`: 시계 방향 각도 (0~359도)
- 기준점: 가구 중심

### 가구 편집 제약
- 가구 종류 카탈로그의 기본 크기는 cm 단위이며, 같은 종류를 여러 개 추가할 수 있다.
- 벽 좌표는 **벽 중심선**이다. 가구를 놓을 수 있는 바닥은 각 벽을 두께의 절반만큼 방 안쪽으로 민 면(안쪽 면)으로 둘러싸인 다각형이다(`room-plan/model/roomInterior.ts`).
- "가구가 방 안에 있다"의 판단은 `furniture/model/roomFit.ts` 하나로 통일한다. 편집기 이동·크기·회전, 추천 요청 전 확인, AI 추천 검증이 모두 같은 규칙을 쓴다. 벽이 닫히지 않은 도면은 가로·세로 사각형으로 대신 판단한다.
- 이동·크기 조절·회전은 먼저 안쪽 바닥을 감싸는 사각형으로 제한한 뒤, 실제 방 모양에 들어가지 않으면 한 축만 움직여 벽을 따라 미끄러지게 하고, 그래도 안 되면 직전 상태를 유지한다. ㄱ자 방의 빈 공간으로는 들어가지 않는다.
- 도면을 나중에 바꿔 이미 방 밖이 된 가구는 자동으로 옮기지 않는다. 편집 화면에서 빨간 테두리와 경고로 보여 주고, 사용자가 자유롭게 끌어 다시 넣을 수 있다. 방 밖 가구가 있으면 AI 추천 요청을 막는다.
- 이 보정은 `FurnitureItem`의 `x`, `y`, `width`, `height`, `rotation`만 갱신하며 벽·문·창 데이터는 변경하지 않는다.

## 스캔 전략
- **iOS LiDAR 기기**: RoomPlan API → 자동 도면 생성
- **일반 기기**: 카메라 촬영 → 수동 편집
- 두 경로 모두 동일한 `RoomFloorPlan` 스키마로 합류

## AI 추천
- OpenAI GPT-4o Vision API 사용
- Supabase Edge Function 경유로 API 키 보호
- 입력은 도면 좌표·가구 용도·선택 스타일이며, 스크린샷은 선택 사항이다. 모델에 전달하는 가구의 `x/y`는 중심 좌표다. 벽의 끝점과 개구부의 시작점은 그대로 전달한다. 앱은 벽 안쪽 면 다각형을 `roomInterior`로 함께 보내고, 프롬프트는 벽 좌표가 중심선이며 가구는 `roomInterior` 안에 둬야 한다고 설명한다.
- 형식 검사(함수)와 배치 검증(앱)에서 탈락한 후보는 사유를 로그로 남긴다. 함수는 `console.warn`, 앱은 개발 모드에서만 `[recommendation]` 경고를 출력한다.
- 모델은 후보 3개에 가구별 ID와 중심 기준 `x/y/rotation`을 반환한다. 함수는 원본 치수와 종류를 복원하고 중심을 앱에서 사용하는 회전 전 좌상단 좌표로 변환한다. 누락·중복·미등록 ID가 있는 후보는 제외한다.
- `minimal`은 넓게 이어지는 빈 공간, `modern`은 현재 가구로 구성할 수 있는 용도별 구역, `nordic`은 기존 소파나 침대를 중심으로 통로에서 벗어난 휴식 공간을 우선한다. 선택한 기준은 방 모양과 가구 용도에 맞을 때 적용하며, 가구 접근과 사용을 우선한다. 함수는 결과의 실제 배치 선택 한 가지와 그 이유를 한국어로 설명하도록 요청한다.
- 도면 편집(STEP 1)에서 사용자는 방 치수와 벽 꼭짓점, 문·창을 입력한다. 벽을 눌러 문·창을 추가하고, 문·창을 눌러 폭을 바꾸거나 벽을 따라 끌어 옮긴다(`room-plan/model/openingEditing.ts`). 문·창은 벽 끝이나 이웃한 문·창을 넘어가지 않는다. '직접 도면 만들기'는 문 1개만 기본으로 넣는다.
- 기록된 문은 동선 검증에 사용한다. 창 위치는 도면 데이터로만 전달하며, 스타일별 프롬프트는 창이나 채광에 의존하지 않는다.

## 편집 흐름과 상태 경계

- 편집 흐름은 `도면 설정 → 가구 배치 → 스타일 선택 → 추천 결과` 네 화면으로 분리한다.
- 단계 사이의 `RoomFloorPlan`은 초안 저장소의 `draftId`로 전달한다. 화면은 `useWorkflowDraft()`로 초안을 읽고 고치며, 초안을 찾지 못하면 예시 도면으로 대체하지 않고 만료 화면을 보여 준다.
- 가장 최근 초안 하나를 기기(AsyncStorage)에 저장한다. 드래그 중 잦은 수정은 잠시 모아 저장하고, 앱이 백그라운드로 가면 즉시 저장한다. 앱을 다시 켜면 메인 화면을 열기 전에 불러오며, 저장값이 깨졌거나 형식이 맞지 않으면 버리고 빈 상태로 시작한다. 홈의 '이어서 편집하기'는 이 초안으로 돌아간다.
- 도면 설정은 벽·꼭짓점·개구부 좌표만, 가구 배치는 `furniture` 배열만 수정한다.
- 추천 요청은 버튼을 누른 시점의 최신 초안으로 보낸다. 요청 화면을 벗어나거나 초안이 바뀌면 진행 중이던 결과를 표시하지 않는다.
- AI 추천 결과는 메모리 세션이며, 사용자가 '적용하기'를 누를 때만 초안의 `furniture`를 바꾼다. 추천을 요청한 도면이 그대로일 때만 적용할 수 있다.
- 적용 직후 가구 편집 화면에서 한 번 되돌릴 수 있다. 적용 뒤 가구를 직접 고치면 고친 내용을 지키기 위해 되돌리기를 없앤다. 되돌리기 정보는 앱을 다시 켜면 사라진다.
- 가구 카탈로그는 `features/furniture/catalog/furnitureCatalog.ts`에서 종류와 모양을 정의한다. 새 모양에는 고유한 프리셋 ID, 기본 치수, 0~1 좌표의 외곽선과 내부 요소를 추가한다. 화면의 카테고리 ID는 공통 `FurnitureType`과 별개라서, 같은 공통 타입으로 여러 카테고리를 만들 수 있다.
- 도면에는 가구별 실제 치수와 선택한 `catalogId`를 저장한다. 이전 도면처럼 ID가 없으면 해당 종류의 기본 프리셋을 사용한다. 썸네일·편집·추천 화면은 같은 그림을 사용하며, 선택 범위는 프리셋의 외곽선을 따른다.
- 후보와 자동 보정에 같은 검증을 적용한다. 실제 벽 안쪽에 가구와 사용 공간이 들어가야 하며 출입구 앞과 옷장·서랍장·일부 가전의 앞면을 비워야 한다. 문 열림 방향 정보가 없으므로 문 폭만큼, 최대 90cm를 문 앞 공간으로 사용한다. 러그는 바닥 면적을 다른 가구와 공유할 수 있다.
- 현재 도면에서 사용 방향과 거리가 맞는 책상·화장대·식탁이 하나인 의자는 그 가구와의 관계를 추천 후보와 자동 보정에서도 유지한다. 검증을 통과한 후보는 소파와 TV장 방향, 의자와 책상·식탁의 위치 관계를 기준으로 정렬한다. 새 배치를 만들지 못해 현재 배치를 표시하거나 앱이 위치를 조정하면 결과에 표시한다.
