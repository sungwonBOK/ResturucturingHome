# 방 도면·가구·AI 추천 분리 UX 설계

## 목표

사용자가 한 화면에서 모든 작업을 처리하지 않도록 방 도면 설정, 가구 배치, 스타일 선택, AI 추천 결과를 순서대로 분리한다. AI 추천 결과는 보기 전용이며 현재 편집 도면이나 저장된 방을 변경하지 않는다.

## 범위

포함:

- 홈과 스캔 진입점에서 같은 도면 초안을 시작한다.
- 자유 형태 방의 꼭짓점과 벽을 첫 화면에서 직접 편집한다.
- 가구를 별도 화면에서 카탈로그로 추가하고, 휴대폰에서 이동·크기 조절·회전한다.
- AI가 제안하는 세 가지 배치 종류 중 하나를 고르고, 해당 종류의 대표 AI 배치 한 개를 결과 화면에서 도면과 설명으로 확인한다.
- 뒤로가기로 이전 단계에 돌아가도 같은 초안과 편집 내용이 유지된다.

제외:

- AI 추천 배치를 현재 도면에 적용하거나 서버에 저장하는 기능
- 단계별 자동 저장, 앱 재시작 뒤 초안 복구, 신규 인증/데이터베이스 변경
- 실제 RoomPlan, ARCore, 사진 분석 파이프라인 변경

## 사용자 흐름

1. 사용자는 홈의 `배치 추천받기` 또는 스캔 플로우에서 편집 초안을 만든다.
2. `도면 설정` 화면에서 방의 폭·높이, 꼭짓점, 벽을 조절하고 `가구 추가하기`를 누른다.
3. `가구 배치` 화면에서 카탈로그에서 가구를 추가하고, 선택한 가구를 드래그·크기 조절·회전한 후 `AI 배치 추천받기`를 누른다.
4. `스타일 선택` 화면에서 AI가 제안하는 미니멀·모던·노르딕 세 배치 종류 중 하나를 선택하고 추천을 요청한다.
5. `추천 결과` 화면에서 선택한 종류의 대표 배치 한 개를 도면과 설명으로 본다. 다른 종류를 보려면 스타일 선택으로 돌아간다. 결과에서 뒤로가면 스타일 선택으로, 계속 뒤로가면 가구 및 도면 설정으로 돌아간다.

## 화면과 책임

### 1. 도면 설정

`room-plan-setup` 라우트와 `features/room-plan` 폴더가 책임진다. 이 화면은 방 윤곽과 개구부를 렌더링하고 꼭짓점 또는 벽의 위치를 수정한다. 가구 카탈로그, AI 요청, 저장 UI를 포함하지 않는다.

자유 형태 방은 순서가 유지된 닫힌 벽 고리로 표현한다. 꼭짓점을 옮기면 인접한 두 벽의 끝점만 갱신한다. 폭과 높이는 현재 윤곽의 경계 상자이며, 방 벽·문·창의 좌표는 cm 단위를 유지한다. 유효성 검사는 3개 이상 꼭짓점, 길이 30cm 이상 벽, 자기 교차가 없는 닫힌 윤곽을 요구한다. 문과 창은 연결된 `wallId`를 유지하며, 해당 벽이 이동할 때 벽의 상대 위치를 보존해 함께 이동한다.

### 2. 가구 배치

`furniture-editor` 라우트와 `features/furniture` 폴더가 책임진다. 카탈로그는 `catalog` 폴더의 데이터와 조회 함수로 제한하고, 편집 규칙은 `model` 폴더의 순수 함수로 제한한다. 새 가구 타입은 도메인 타입과 카탈로그 항목만 추가하면 되며, 화면·제스처 코드에 타입별 분기가 생기지 않는다.

제스처는 Skia `Canvas`에 직접 `PanResponder`를 붙이지 않는다. `react-native-gesture-handler`의 `GestureDetector`와 가구별 투명 오버레이를 사용해 선택·이동·크기 조절·회전을 처리한다. 오버레이는 Skia 가구의 위치·크기·회전을 그대로 반영한다. 제스처는 회전된 좌표계에서 cm 단위로 변환한 뒤 순수 가구 편집 함수에 전달한다.

### 3. 스타일 선택

`recommendation-style` 라우트와 `features/recommendations/style-selection`이 책임진다. 이 화면은 세 스타일과 요청 버튼만 제공하며, 도면을 수정하지 않는다.

### 4. 추천 결과

`recommendation-results` 라우트와 `features/recommendations/results`가 책임진다. 선택한 종류의 대표 추천 하나만 읽기 전용 도면과 설명으로 표시한다. 추천 결과는 초안 상태와 분리된 메모리 상태로 보관하며, 편집 도면이 변경되면 결과를 폐기한다. 현재 Edge Function이 반환하는 세 후보 중 첫 번째 후보를 해당 종류의 대표 배치로 저장한다.

## 초안 상태와 라우팅

초안 저장소는 `create`, `get`, `update`를 제공한다. 초안 식별자는 모든 단계의 라우트 파라미터로 전달하며, 수정 화면은 `update(draftId, plan)`만 호출한다. 이 저장소는 이번 범위에서는 메모리 저장소이므로 앱 재시작 뒤 초안이 사라지는 것은 의도된 동작이다. 사라진 초안으로 진입하면 명확한 만료 상태와 새 도면 시작 CTA를 표시한다.

## 오류 처리

- 유효하지 않은 방 윤곽에서는 다음 단계 CTA를 비활성화하고 어떤 규칙을 만족하지 않는지 표시한다.
- 추천 요청 중에는 중복 요청을 막고 진행 상태를 표시한다.
- 요청 실패는 현재 스타일 선택 화면에 한국어 오류와 재시도 버튼으로 표시한다.
- 오래된 요청 결과는 도면이나 선택 스타일이 바뀐 뒤 표시하지 않는다.

## 검증

- 순수 도면 윤곽 편집: 닫힌 고리, 최소 벽 길이, 자기 교차, 문·창의 벽 상대 위치를 단위 테스트한다.
- 순수 가구 편집: 추가, 이동, 크기 조절, 회전, 방 경계 제약과 신규 카탈로그 항목을 단위 테스트한다.
- 제스처 좌표 변환과 핸들 hit-test를 단위 테스트하고 Expo Go에서 실제 드래그·리사이즈·회전을 확인한다.
- 초안 저장소 업데이트와 화면 간 동일 `draftId` 전달을 테스트한다.
- 추천 서비스의 스타일별 정확히 세 결과 검증, 대표 한 개 선택, 오래된 결과 무시를 테스트한다.
- 모바일과 도메인 타입 검사, `git diff --check`를 실행한다.
